## Findings, ordered by remediation priority

### P1: U03 worker can ACK without a durable terminal update

- BR-U03-53 and BR-U03-56 require ACK after handler state update and terminal failure persistence (`aidlc-docs/construction/u03-job-and-settings/functional-design/business-rules.md:66`).
- `backend/src/main/java/edu/aiplatform/jobs/application/JobDispatcher.java:89` catches an exception from `handler.onFailed(...)`, logs it, and still returns FAILED. `backend/src/main/java/edu/aiplatform/jobs/infrastructure/JobListener.java:57` calls `basicAck` in `finally` at line 64 even when dispatch/retry publication throws. The message can disappear while the owner row is still pending/running.
- Existing `JobDispatcherTest.permanentErrorFailsAtOnce` (`backend/src/test/java/edu/aiplatform/jobs/application/JobDispatcherTest.java:100`) uses a successful in-memory onFailed. There is no JobListener test in the reviewed package. Add failure-persistence and retry-publication failure cases asserting requeue/no ACK until terminal persistence or retry handoff succeeds. Classification: production-code BR risk plus important missing assertions, not a failing existing test.

### P1: U03 backup success test accepts failed CAS transition

- BR-U03-92/59 require correct terminal state/idempotency (`aidlc-docs/construction/u03-job-and-settings/functional-design/business-rules.md:104`, `:70`).
- `BackupJobHandlerTest.successfulRunStoresAnEncryptedArchiveThatDecryptsToTheDump` (`backend/src/test/java/edu/aiplatform/backup/application/BackupJobHandlerTest.java:95`) stubs markRunning=1 but never stubs markSuccess. Mockito therefore returns 0. The handler ignores that result at `backend/src/main/java/edu/aiplatform/backup/application/BackupJobHandler.java:112`, records BACKUP_COMPLETED and purges anyway.
- `BackupRunRepository.markSuccess` is a conditional SQL update of RUNNING only (`backend/src/main/java/edu/aiplatform/backup/domain/BackupRunRepository.java:50`). Fix the success fixture to return 1 and add markSuccess=0 as its own no-success-audit/no-purge case. Also exercise duplicate concurrent delivery: markRunning accepts RUNNING (`:44`), so sequential finishedRunIsSkipped does not establish concurrent idempotency. Classification: misleading success fixture and missing assertion exposing production-code risk.

### P1: U03 'safe error' assertions do not establish secret redaction

- BR-U03-95 requires masked failure errors (`aidlc-docs/construction/u03-job-and-settings/functional-design/business-rules.md:107`).
- `JobDispatcher.safe` (`backend/src/main/java/edu/aiplatform/jobs/application/JobDispatcher.java:105`) prefixes the exception class and truncates its original message. `BackupJobHandler.onFailed` (`backend/src/main/java/edu/aiplatform/backup/application/BackupJobHandler.java:128`) truncates again, then persists/audits/emits that same string at lines 129, 135 and 139.
- `JobDispatcherTest.safeErrorHasNoStackTraceAndIsShort` (`backend/src/test/java/edu/aiplatform/jobs/application/JobDispatcherTest.java:134`) checks length and timeout wording only. `BackupJobHandlerTest.failureMarksTheRunCleansUpAuditsAndNotifies` (`backend/src/test/java/edu/aiplatform/backup/application/BackupJobHandlerTest.java:136`) uses a benign Drive error and checks action/event type. Neither would catch an exception message containing an API key/password/token.
- Add sentinel secrets in exception messages and assert their absence from audit.reason, backup.safe_error, event payload and log output, with a deliberate safe error mapping. Classification: missing assertions and source-observed sanitization gap, not evidence that an actual production secret was leaked.
