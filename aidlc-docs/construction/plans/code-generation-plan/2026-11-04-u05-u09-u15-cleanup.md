# U05/U09/U15 audit remediation — implementation plan

Status: implemented and automated verification passed; manual browser acceptance deferred because Orca CLI is unavailable. See the execution results for evidence and limits.

## Goal and baseline

Resolve the five findings from the source audit at `45baad9b`: grading navigation loses filters, gradebook/export repeats whole-class work, conflict messages hide business errors, grading calculations live in a UI component, and class creation repeats a permission check.

Architecture: retain the existing unit contracts and controller/service/repository boundaries. Add optional navigation filters to the evaluation HTTP read, reuse batched account lookup and build request-local indexes for gradebook assembly. Move existing pure grading functions into the feature model without changing their behavior.

Stack: Java 17/Spring, PostgreSQL, Next.js/React/TypeScript, JUnit/Mockito, Vitest.

Specifications: U09 `functional-design/business-rules.md` (especially BR-U09-12), U05/U09/U15 `code/as-built-baseline.md`, and README structure conventions. All unit paths are under `aidlc-docs/construction/`.

Existing verification at this baseline: backend 1,764 passed with zero skips; frontend 743 passed; lint, TypeScript and both production builds passed. These results are historical evidence for this plan, not validation of future changes.

## Constraints and acceptance criteria

- No database/schema migration, new dependency, shared cache or grading-policy change.
- Preserve authorization, audit writes, transaction boundaries, version checks, FINALIZED/PUBLISHED locks, resubmission resets, proposal validation and export formula escaping.
- Existing evaluation URLs and MCP/server calls without navigation filters retain ALL behavior.
- Workspace previous/next and save-next follow the originating status/late filters, in the same deterministic order as the filtered submission listing. Select next before saving, because saving may remove the current row from a PENDING filter. Stay on the saved evaluation if no next eligible evaluation exists.
- Rows without an evaluation ID cannot become navigation targets. Recheck scope/current receipt before accepting any write; navigation is not an authorization mechanism.
- Explicit search/select student remains an intentional switch across the assignment; clear the originating filter context for that switch so navigation never silently uses an incompatible queue.
- Gradebook/export output, ordering, official-score visibility and active-enrollment selection remain equivalent. Missing account contacts keep the existing fallback.
- U15 has no verified remediation item; retain its source unchanged and include its tests in regression checks.
- Security baseline remains enabled for the existing unit scope. Preserve existing resiliency choices; PBT stays disabled. No infrastructure change is required.

## Review focus and limits

1. Saving PENDING to DRAFT changes filter membership: Task 1 must select next from the pre-save queue.
2. A learner resubmits or leaves the class while the workspace is open: Tasks 1/2 retain server checks and current-attempt selection.
3. Group rows and member overrides differ from individual attempts: Tasks 1/2 test both explicitly.
4. Missing contacts and empty classes must not corrupt export output: Task 2 checks fallback and header-only output.
5. A second teacher finalizes a grade while edits are unsaved: Task 3 reports GRADE_LOCKED accurately and retains local input without retrying.

Rollback is an ordinary revert of the relevant code commit; no data rollback is needed. Large-scale load testing, a complete UI redesign, new architecture frameworks and a blanket reformat are excluded. The gradebook optimization reduces repeated work but does not make an unbounded class dataset free to load.
