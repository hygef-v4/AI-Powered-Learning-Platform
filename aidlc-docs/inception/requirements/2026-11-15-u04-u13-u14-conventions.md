# U04/U13/U14 — áp dụng quy ước mã nguồn: yêu cầu

Độ sâu: Minimal. Nguồn: lần rà soát ngày 2026-11-15 (mục "Rà soát quy ước mã nguồn U04/U13/U14" trong `aidlc-docs/audit.md`) và [câu trả lời Q1–Q5](2026-11-15-u04-u13-u14-conventions-questions.md) (Q1–Q4 chọn A; Q5 làm trên nhánh `fix/code-conventions-u04-u13-u14`). Quy ước áp dụng: [code-conventions.md](../../construction/code-conventions.md).

## Intent

- **Loại**: refactor đặt tên và trình bày. Không thêm chức năng, không đổi hành vi.
- **Phạm vi**: U04 (`subjects`), U13 (`materials`), U14 (`announcements`, `notifications`). Gồm backend main, test backend, frontend `features/*` tương ứng và test frontend.
- **Độ phức tạp**: vừa. Nhiều file bị ảnh hưởng, nhưng mỗi thay đổi là đổi tên cơ học.

## Yêu cầu

| ID | Yêu cầu | Quy ước |
|---|---|---|
| CC-01 | Field và tham số constructor của dependency service dùng tên kiểu viết `lowerCamelCase` có hậu tố `Service`, ví dụ `SubjectCommandService subjectCommandService`. Dependency không phải service đặt theo đúng type, bỏ tiền tố `I`, ví dụ `ISubjectRepository subjectRepository`, `IClassAccess classAccess`, `IAccountLookup accountLookup`, `IEventPublisher eventPublisher`, `ISseHub sseHub`. Áp dụng cho service, adapter, controller và test. | §3 |
| CC-02 | Method/function nghiệp vụ đặt theo mẫu động từ + đối tượng. Đổi cả tên danh từ hoặc HTTP verb (`detail`, `classes`, `information`, `status`, `mine`, `get`, `put`, `unread`, `versions`, `stalePending`, `proposalLink`…) và động từ đứng một mình (`list`, `create`, `update`, `delete`, `edit`, `save`, `record`…). Đọc danh sách dùng `list`, đọc chi tiết dùng `load`, tìm dùng `find`, cấp token dùng `issue`, kiểm tra dùng `is/has/can/require`. | §4 |
| CC-03 | Biến và tham số có tên nghiệp vụ. Không dùng một chữ cái (`m`, `v`) trong phạm vi dài. Không dùng tên kỹ thuật chung chung (`json`, `jdbc`, `em`) khi có tên theo type (`objectMapper`, `jdbcClient`, `entityManager`). | §5 |
| CC-04 | Dòng code dài khoảng 100 ký tự trở xuống. Xuống dòng danh sách tham số và chuỗi gọi `.param(...)`. Tách lambda lồng sâu trong `MaterialModuleService` thành method riêng. Không bắt buộc tách SQL, literal hay URL. | §6 |
| CC-05 | Frontend: file chứa hook đặt `use...` (`subjectMutation.tsx` → `useSubjectMutation.tsx`). File chứa component đặt `PascalCase` (`moduleNav.tsx` → `ModuleNav.tsx`). Hàm và method của object API đặt động từ + đối tượng (`materialError` → `describeMaterialError`, `materialApi.token` → `issueDownloadToken`, `notificationsApi.count/preferences` → `countUnread`/`loadPreferences`…). Cập nhật import ở mọi nơi dùng. | §2, §4 |
| CC-06 | Cập nhật tài liệu hiện hành có nhắc tên cũ: code summary và as-built của U04/U13/U14. Không sửa kế hoạch và báo cáo lịch sử. | §1, §7 |

## Ràng buộc (không đổi)

- URL, HTTP method, tên trường JSON và DTO/record, schema DB, migration, event, tên MCP tool, queue và job type.
- Public contract `subjects.contract` (`ISubjectQuery`, `ISubjectClasses`, `ISubjectMutationGuard`, stub) và caller ở unit khác.
- Method framework, override và accessor record: `handle`, `jobType`, `queue`, `timeout` của JobHandler; `tools`, `call` của MCP; `afterCommit`; `@ExceptionHandler` chỉ đổi khi không phải chữ ký framework; Spring Data derived query (`existsByCode`, `findById`…).
- Validation, phân quyền, transaction, khóa và version, audit, side effect, accessibility, tên class CSS.
- Tên test là câu mô tả hành vi, không ép theo quy tắc method.

## Ngoài phạm vi

- Chuyển JPA sang JDBC (U04, module U13, U14), theo [persistence-conventions.md](../../construction/persistence-conventions.md).
- Đổi tên contract hoặc code của unit khác.
- Commit, push và deploy khi chưa được yêu cầu.

## Kiểm chứng

- Backend: compile và chạy toàn bộ test (`mvn -o -B verify`, gồm ArchitectureTest).
- Frontend: TypeScript, ESLint và Vitest cho các feature bị sửa cùng caller; build nếu có đổi tên file.
- Rà diff để chắc chỉ đổi tên và trình bày: không đổi chuỗi URL, JSON hay SQL.
- Grep lại các mẫu vi phạm trong lần rà soát.

## Extension

- Security Baseline: không đổi xác thực, phân quyền, validation hay log. Kiểm qua test hiện có.
- Resiliency Baseline: không đổi timeout, retry, khóa hay transaction.
- PBT: tắt.
