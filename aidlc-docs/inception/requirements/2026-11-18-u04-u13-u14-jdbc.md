## Intent

- **Yêu cầu**: "giúp tôi tạo branch mới từ staging để sửa lại từ jpa sang sử dụng jdbc cho cả 3 unit".
- **Loại**: migration công nghệ persistence; không đổi chức năng.
- **Phạm vi**: U04 (`subjects`), U13 (`materials`, phần module), U14 (`announcements`, `notifications`): backend main và test backend. Không đổi frontend.
- **Độ phức tạp**: vừa đến cao. Code ít, nhưng phải giữ khóa, CAS, timeout và trạng thái email mà JPA đang làm ngầm.
- **Nhánh**: `refactor/jdbc-u04-u13-u14` từ `staging@2e179598`.

## Yêu cầu chức năng

| ID | Yêu cầu |
|---|---|
| JD-01 | Production của U04, U13, U14 không còn dùng `jakarta.persistence`, `org.springframework.data.jpa`, `org.hibernate` hay `EntityManager`; truy cập PostgreSQL bằng Spring JDBC (`JdbcClient`/`JdbcTemplate`/`NamedParameterJdbcTemplate` có sẵn), theo cách code JDBC xung quanh đang dùng. |
| JD-02 | U13: `MaterialModuleRepositoryAdapter` chạy cùng SQL qua JDBC; giữ CAS theo `version`, `@Transactional(timeout = 10)`, thứ tự `order_no,id` và `order_no,created_at,quiz_id`. |
| JD-03 | U14 announcements: bỏ annotation JPA khỏi `Announcement`, giữ class và field. Repository map bằng row mapper; insert ghi version 0; update giữ CAS `version` + `status='ACTIVE'`, tăng version 1 và cập nhật `announcement.version` khi thành công; danh sách giữ thứ tự `created_at desc, id desc`, phân trang và trả rỗng khi không có lớp. |
| JD-04 | U14 notifications: bỏ annotation JPA khỏi `Notification`, `EmailDelivery`; xóa `NotificationPreference`, `DeadlineReminder` (chỉ là mapping JPA, không service nào dùng). Giữ SQL `on conflict`, advisory lock `14002000` với `lock_timeout` 2s, giới hạn 100/300 bản ghi, xóa lô 10.000, thứ tự hiện có. |
| JD-05 | U14 email: thêm thao tác ghi tường minh `EmailDelivery` và gọi ở mọi nhánh `EmailDeliveryService` đang dựa vào dirty checking (`sendEmail`, `markEmailFailed`, `releaseDeferredEmails`). Giữ: `attempts` tăng được lưu khi gửi mail lỗi (`noRollbackFor = RetryableJobException`); email chuyển PENDING được ghi trước lần đếm hạn mức kế tiếp; `lockEmailDelivery` khóa hàng `for no key update` với cùng hành vi chờ đã đo (Hibernate bỏ qua hint 2s; timeout chỉ có khi caller đã gọi `lockEmailBudget`). |
| JD-06 | U04: xóa `ISubjectJpaRepository`, `SubjectJpaEntity`; `SubjectRepositoryAdapter` dùng JDBC và map thẳng sang `Subject`. Giữ: storage version = public version − 1 (insert 0); CAS `updateSnapshot` theo id + version + code, không đổi `code`/`created_at`; khóa hàng cùng chế độ khóa Hibernate đang sinh (kiểm câu SQL thật trước khi chuyển); giới hạn lock/statement timeout ≤ 1s và khôi phục giá trị cũ; yêu cầu `READ COMMITTED`; tìm kiếm `lower(...) like ... escape '!'`, sắp `code`, đếm theo trạng thái; kiểm tra `page`/`size`. |
| JD-07 | U04: `SubjectCommandService` nhận diện trùng mã qua constraint `uk_subjects_code` từ lỗi JDBC/PostgreSQL thay cho class Hibernate; vẫn trả `SUBJECT_CODE_DUPLICATE`, lỗi khác ném lại. |
| JD-08 | `NotificationExceptionHandler`: bỏ handler `PersistenceException`. Đã kiểm khi làm Step 3: `@Repository` (PersistenceExceptionTranslationPostProcessor) và `JpaTransactionManager` đã dịch mọi lỗi JPA thành `DataAccessException` trước khi tới controller, nên handler này không bao giờ chạy; lỗi DB vẫn đi tới `GlobalExceptionHandler` như hiện tại (503 `SYSTEM_BUSY` khi DB không khả dụng hoặc timeout). Bắt `DataAccessException` tại đây sẽ đổi phản hồi của lỗi DB khác nên không làm. |
| JD-09 | ArchitectureTest thêm rule cấm JPA/Hibernate trong `subjects`, `materials`, `announcements`, `notifications`. |

## Ràng buộc: không ảnh hưởng unit khác (Q1)

- Giữ `spring-boot-starter-data-jpa`, cấu hình `spring.jpa` và `JpaTransactionManager` chung. Repository JDBC của ba unit tham gia transaction qua cùng DataSource như U05/U09 đang làm.
- Không sửa code production, contract hay test của unit khác. Ngoại lệ duy nhất là file test dùng chung khi bắt buộc để biên dịch: `OwnerRequirementsTestConfig` (đang import ba unit và tham chiếu `ISubjectJpaRepository`) và `ArchitectureTest` (chỉ thêm rule). `EvaluationVersionIntegrationTest` (U09) quét package `subjects.repository`; không sửa nếu vẫn chạy được, nếu phải sửa sẽ báo trước.
- Giữ URL, JSON, DTO, schema, migration, event, job type, public contract `subjects.contract`, quyền, audit, side effect.

## Yêu cầu phi chức năng

- **Đúng đắn đồng thời**: giữ khóa hàng, advisory lock, thứ tự khóa (budget trước row), CAS và kiểm affected rows; không thay CAS bằng đọc-rồi-ghi.
- **Bảo mật (SECURITY)**: bind mọi tham số; không nối đầu vào người dùng vào SQL; lỗi API không lộ SQL.
- **Chịu lỗi (RESILIENCY)**: giữ lock/statement/transaction timeout, retry email và trạng thái sau lỗi mail.
- **Kiểm chứng (Q3)**: viết test characterization trên PostgreSQL (Testcontainers, migration thật) khi code còn JPA, chạy đạt; giữ nguyên bộ test đó sau khi chuyển. Cuối cùng chạy `mvn -o -B verify` toàn backend. Không hạ ngưỡng, không skip test.
