# Report 4 diagram sources

`class-diagrams.json` describes selected real Java classes and interfaces, each in its own box. Displayed methods retain every named parameter and the return type. Parameter types are omitted, while attributes retain types and `sourceOperations` retain full Java declarations. The six views are Authentication, Assignment Authoring and Publication, Assignment Workspace and Submission, Grading and Practice Feedback, AI API Task Processing, and MCP Integration. These views select the methods relevant to the report.

Since 2026-11-18 class relationships follow UML notation checked against the Java fields: a class that keeps a reference in a field draws a directed association (solid line, open arrow); a registry that collects independently managed Spring beans draws a shared aggregation (open diamond at the registry); temporary use such as a repository returning an entity stays a dependency (dashed line, open arrow); `implements` is a realization (dashed line, open triangle); parts that cannot exist without their owner use composition (`Assignment` ◆ `DocumentPart`, `Evaluation` ◆ `EvaluationHistory`, `GroupDocument` ◆ `GroupSection`). Every Java interface is labelled «interface». Edges are routed orthogonally with as few bends as possible (straight first, then one or two bends) and never pass through a box. The Grading page (trial layout, 2026-11-18) puts classes of the same level on one row: controllers, then services (services that call each other sit side by side), then repositories, then entities; each controller sits above its service and each entity below its repository, uses fixed box widths (about 280 px for controllers and services, 250 px for repositories and interfaces) and wraps long method signatures after a parameter, keeping every parameter and return type. The Grading page shows only the main classes: interfaces are omitted (services point at the implementing repository, and `AiTaskService` stands for `IAiTask`), and `GradingBatchService` and `AttemptRepository` are left out. On the Grading page aligned classes are joined by straight horizontal or vertical lines (no diagonals); several classes pointing at the same class with the same arrow share one orthogonal bus that enters the target as a single line with one arrow head, and one class pointing at several classes splits from a shared trunk. Bars of different groups sit at least 30 px apart. In the earlier Grading trial, where two services each used both repositories (`GradingProposalTransactions`, `GradingProposalService`), each repository sits under the service that uses it most, and the two cross-column edges are single diagonal lines into the repository side, crossing once.
